# Tracking input contracts

Thin/thick NKM trackers, both ring tracking interfaces, and beam statistics use
shared particle validation from `nkm_injection.tracking_contracts`. Split and RK4
integrators share validated parameter setup and transverse drift operations;
their second-order split and fourth-order RK4 algorithms remain separate.

## Coordinates and loss representation

Supply a real numeric `(6, N)` array in AT order `(x, px, y, py, delta, ct)`:
positions and ct in m, transverse momenta in the existing rad convention, delta
dimensionless. Integer inputs become float64 arrays. Tracking returns independent
writable storage and does not mutate caller arrays. Transposed/wrong-shaped,
complex, boolean, object and nonnumeric arrays are rejected. A square `(6, 6)`
array is interpreted in coordinate-row order; callers remain responsible for
its orientation.

Active columns must contain six finite coordinates. Accepted already-lost
columns are either all-NaN or NaN in x with five finite remaining coordinates.
Other partial NaNs and every Inf in user-supplied arrays are invalid. Lost
columns retain their input values and column positions; arrays are not compacted.
Empty `(6, 0)` beams are supported, as are beams with no active particles.

Ring results record `metadata['initial_lost_indices']`. Those particles remain
in the total-particle denominator and are not logged again as new losses.
Physical aperture/septum checks retain original indices. Element tracking logs
new backend losses once using `cause='at_tracking_loss'`, with turn/element and
available s position. Its x/y event coordinates are the last finite coordinates
at the element entrance, rather than an inferred impact point inside the element.

The installed AT single-element aperture pass uses `ct=+Inf` with five finite
other coordinates as a loss sentinel. This exact backend-return pattern is
normalized to an all-NaN column before public validation. It is not accepted in
user inputs. AT NaN-x loss markers are also accounted for. Other malformed
backend coordinates fail validation; generated nonfinite coordinates in the
NKM integrators or linear one-turn map are numerical errors, not physical losses.

## Parameters and migration

- Slice and turn counts require actual positive Python/NumPy integers; booleans,
  floating counts (even `2.0`), zero and negative counts are rejected.
- Element length in m and dimensionless field scale must be finite and
  nonnegative. Zero thick-element length returns the input copy. Zero scale
  performs only the transverse drift and avoids field evaluation. An integrated
  thin kick can remain nonzero at zero geometric length because its supplied
  integrated strength is independent of the drift length.
- Beam energy must be finite and strictly positive. Existing NKM interfaces take
  GeV and convert explicitly to eV; ring configurations use eV.
- Charge in C must be finite and nonzero. Both signs are supported. Rigidity must
  remain finite and positive in T m. Thick trackers use their charge argument;
  thin tracking uses the charge in kick metadata for integrated-field conversion.
  Already tabulated angle kicks retain their declared sign convention.
- Field/kick callables must return two finite real components that broadcast to
  the active particle vector. Thick fields use `(By, Bx)` in T; thin components
  use the existing metadata-defined angle or integrated-field units and order.
  Field-map bounds from Task 03 still apply whenever fields are evaluated.

Previously zero-turn calls returned the initial beam. Use
`TrackingResult.from_beam(beam)` or `compute_beam_statistics(beam)` for that
purpose; zero-turn tracking now raises before accessing a lattice. Normalize
legacy counts explicitly only after verifying they are integral. Negative field
scales are unsupported; express the intended sign in field values/charge.

`StorageRingInjectionConfig` now accepts zero NKM geometric length in its domain
validation. Historical result files are not rewritten. Result metadata adds
initial lost indices and loss logs now include backend losses that were
previously omitted. Statistical treatment of undefined emittance/empty-beam
statistics remains unchanged and is outside this refactor.

## Numerical verification

Contract checks use exact shape/type/finite tests. Regression drift and uniform
field kicks compare with zero relative tolerance and absolute `1e-14` (m or rad
as appropriate), including charge reversal. Analytic linear focusing uses
`By=(1 T/m)*x`, 4 GeV electrons, length 0.5 m and 80 slices: split results use
absolute `1e-9`, RK4 results `1e-14`, with zero relative tolerance. Existing
nonlinear slice-convergence and two-plane integrated-kick tests retain their
established tolerances. No source field data, lattice or protected notebook is
regenerated by these tests.
